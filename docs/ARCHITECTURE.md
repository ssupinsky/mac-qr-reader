# QR Reader — architecture & contracts

Personal, security-focused macOS (arm64, macOS 26) QR reader built on Electron.
This file is the source of truth for module boundaries. Agents working on one
module must not change another module's contract without updating this file.

## Hard requirements (from the owner)

- Security first. Every dependency is vetted; minimize them. **Zero runtime npm
  dependencies.** Dev deps allowed: `electron` (pinned exact), `playwright-core`
  (pinned exact, zero deps) for tests. Anything else needs a written justification
  in `docs/SECURITY.md`.
- No network access by the app, ever (block all requests; nothing is fetched).
- No tracking/telemetry, no i18n.
- **No history**: only the current scan's results live in memory. Nothing decoded is
  ever written to disk (except when the user explicitly uses "Save as…").
- No screen capture, no camera.
- Links: shown with a full security breakdown; opening requires an explicit native
  confirmation dialog shown by the **main** process.
- Run with one command: `./start.sh` (also `npm start`). It installs/verifies deps,
  builds the native helper and the app bundle as needed, then launches.
- Must look great, macOS-native feel, light + dark mode.
- An agent must be able to launch the REAL app and verify it (Playwright `_electron`
  + screenshots). See "Verification".

## Environment facts (verified 2026-11-18)

- Default node is 20.19 but Electron 45 dev tooling wants >=22.12. Node 24.18.0 is
  installed via fnm: use `.node-version` = `24.18.0`; scripts call
  `fnm exec --using=24.18.0 …` when the active node is too old.
- npm registry is the default public registry `https://registry.npmjs.org` (formerly a
  corporate mirror). GitHub (incl. release downloads) is reachable.
- `swiftc` (Command Line Tools) is available. Apple Vision `VNDetectBarcodesRequest`
  works. CoreImage `CIQRCodeGenerator` works (used for test fixtures).
- Chromium's `BarcodeDetector` is NOT available in Electron (even with flags).
- Playwright-core 1.64.1 `_electron.launch()` works with Electron 45.2.3 and can screenshot.

Both helper paths are `fs.realpathSync`-resolved before use. Packaged: their SHA-256s must
match `helper-hashes.json` (checked before the self-test and before every run). If either is
missing, modified, or the sandboxed self-test fails, every scan returns
`error.code = 'decoder_unavailable'`.
Dev-only env vars (ignored when `app.isPackaged`): `QR_DEV_USER_DATA` (userData dir),
`QR_TEST_SENSITIVE_CLEAR_MS` (sensitive-clipboard auto-clear delay), `QR_TEST_HOOKS=1`
(main records returned/pushed `ScanResult[]` in `globalThis.__qrTestLog` for Playwright).

## Native helper contract: `qr-decode`

- Built by `native/build.sh` (= `swiftc -O -target arm64-apple-macos14 -o build/bin/qr-decode
  native/qr-decode.swift`) into `build/bin/qr-decode`; inside the .app it lives at
  `Contents/Resources/bin/qr-decode`. `native/build.sh --fixtures` also builds
  `build/bin/gen-fixtures` and regenerates `test/fixtures/` (+ `manifest.json`).
  Ad-hoc QR image for testing: `build/bin/gen-fixtures one "<text>" out.png`.
- Invocation (by main, via `execFile`/`spawn`, never a shell):
  `sandbox-exec -f qr-decode.sb qr-decode [--preview-max 1600] [--max-pages 10]`
  Image bytes on **stdin** (main enforces a max size, 64 MiB; the helper also enforces it
  and answers `too_large`). JSON on **stdout**, single line. Exit code 0 when JSON was
  written (even for "no codes" and for `ok:false`), non-zero only on catastrophic failure.
  Main enforces a timeout (20 s) and kills the process.
  Testing-only flags (main must not pass them): `--verbose` (timings to stderr),
  `--debug-pass original|inverted|enhanced|upscaled|tile` (run only that pass),
  `--max-footprint-mb N` (16…65536; lowers the memory ceiling below).
  `--preview-max` accepts 64…8192, `--max-pages` 1…100; anything else → `invalid_arguments`.
- Formats (magic-byte allowlist, then ImageIO's detected type must agree): png, jpeg, gif,
  tiff, bmp, webp, ico, heic, heif, avif, pdf. Everything else (SVG, RAW, PSD, ZIP, text…)
  → `unsupported_format`. EXIF/TIFF orientation is applied. GIF: every frame up to
  `--max-pages` is scanned (`pages` = frame count, `page` = frame index; a code repeated on
  later frames is reported once). ICO: largest entry. HEIC/TIFF: primary image only.
  PDF: up to `--max-pages` pages rasterized at 200 DPI (≤ 12 MP per page, ≤ 60 MP total,
  /Rotate honoured); encrypted PDFs that need a password → `decode_error`.
- Limits: header dimensions > 300 MP (or a side > 100 000 px) → `too_large` without decoding;
  images > 24 MP are decoded downscaled to ~24 MP via ImageIO thumbnailing (`width`/`height`
  then describe the downscaled raster; coordinates are normalized so they still apply).
  Pages/frames are decoded and scanned one at a time; only the current page and the preview
  page stay in memory. Between stages the helper checks its own `phys_footprint`
  (`task_info(TASK_VM_INFO)`) and answers `too_large` above 1 GiB. Measured peak footprint:
  7000² PNG 577 MB, 17000² PNG 606 MB, 10-frame 2000² GIF 195 MB, 9000² fixture 466 MB.
- Output:

```jsonc
{
  "ok": true,
  "format": "png" | "jpeg" | "gif" | "tiff" | "bmp" | "webp" | "ico" | "heic" | "heif" | "avif" | "pdf",
  "width": 1200, "height": 800,                      // pixels of the decoded raster of page/frame 0
  "pages": 1,                                        // >1 only for PDFs / multi-frame GIFs
  "preview": { "mime": "image/png" | "image/jpeg", "base64": "...", "width": 800, "height": 533, "page": 0 },
      // long edge <= --preview-max, orientation applied, no metadata. Page = page of the first
      // code (else 0). JPEG for photo formats (jpeg/heic/heif/avif) or very large PNGs.
      // Its own width/height may differ from the top-level ones when page != 0.
  "codes": [                             // sorted by page, then top-to-bottom, left-to-right
    {
      "symbology": "QR" | "MicroQR" | "Aztec" | "DataMatrix" | "PDF417" | "MicroPDF417" | "EAN13" | "EAN8"
                 | "UPCE" | "Code39" | "Code93" | "Code128" | "ITF14" | "I2of5" | "Codabar" | "GS1DataBar" | ...,
                 // = Vision's VNBarcodeSymbology without the "VNBarcodeSymbology" prefix
      "text": "string or null",          // payloadStringValue
      "bytesBase64": "string or null",
      "bytesKind": "payload" | "raw" | null,
          // "payload": QR only — the decoded data segments (byte segments verbatim, numeric/
          //   alphanumeric as ASCII, Kanji as Shift_JIS; ECI/FNC1/structured-append headers
          //   skipped). This is the real payload (equals UTF-8 of `text` for UTF-8 codes).
          // "raw": Vision's payloadData as-is (symbology-specific codewords incl. mode/length
          //   headers — NOT the payload; useful only for hex inspection).
      "bounds": { "x": 0.1, "y": 0.2, "w": 0.3, "h": 0.3 },   // normalized, TOP-LEFT origin, relative to preview/page
      "corners": [[x,y],[x,y],[x,y],[x,y]],                  // normalized top-left origin: TL, TR, BR, BL
      "page": 0,
      "confidence": 1.0,
      "qr": { "version": 3, "ecLevel": "M", "maskPattern": 2 },  // QR only, from CIQRCodeDescriptor
      "pass": "original" | "inverted" | "enhanced" | "upscaled" | "tile"   // which pass found it
    }
  ]
}
// failure:
{ "ok": false, "error": { "code": "unsupported_format" | "empty_input" | "too_large" | "decode_error" | "invalid_arguments", "message": "..." } }
```

- Passes (Vision `VNDetectBarcodesRequest`, latest revision, all supported symbologies; the
  image is flattened onto white first): `original` always; if nothing found: `inverted`
  (also tries flattening transparent images onto black), then `enhanced` (grayscale +
  1–99 % contrast stretch, plus its inverse), then `upscaled` (images < 800 px: nearest-
  neighbour ×2–8 with a white quiet zone); `tile` (2×2 or 3×3 overlapping tiles) runs for
  images ≥ 1800 px even when codes were found, to pick up additional small codes. Optional
  passes are skipped after a 2.5 s soft deadline; later PDF pages get them only while time
  remains.
- Duplicate codes found by multiple passes are de-duplicated (same page + symbology +
  payload and overlapping bounds); the earliest pass wins.
- 1D symbologies are dropped when Vision's confidence is < 0.6 (`original`) or < 0.9 (other
  passes) — text rows in screenshots otherwise yield phantom EAN-13s.

## IPC contract (preload exposes `window.qr`, via `contextBridge`)

All channels are validated in main (sender frame URL must be the app's own origin,
argument types/sizes checked). Renderer never receives filesystem paths.

| method | returns | notes |
|---|---|---|
| `decodeImage(bytes: Uint8Array, meta: {name?: string, source: 'drop'\|'paste'})` | `Promise<ScanResult>` | renderer-obtained bytes (drag-and-drop files, clipboard items found in a paste event) |
| `pasteFromClipboard()` | `Promise<ScanResult[]>` | main reads the system clipboard: image, file URL(s) copied in Finder, or text (text is returned as a "text" result, not decoded) |
| `openFiles()` | `Promise<ScanResult[]>` | native open dialog, multi-select, images + PDF |
| `copyText(text: string, opts?: {sensitive?: boolean})` | `Promise<void>` | sensitive → clipboard auto-cleared after 60 s if still unchanged |
| `openExternal(url: string)` | `Promise<{opened: boolean}>` | main re-validates the URL (allowlist: https, http, mailto, tel, sms, facetime, facetime-audio), shows a native confirm dialog with the exact URL/host, then `shell.openExternal` |
| `saveText({suggestedName, text, kind})` | `Promise<{saved: boolean}>` | native save dialog (vcf / ics / txt / bin — `bin` takes base64 `bytesBase64` instead of `text`) |
| `onScanResults(cb: (results: ScanResult[]) => void)` | unsubscribe fn | pushes from main: Finder "Open With", dock-drop, menu Open, auto clipboard-on-focus |
| `onCommand(cb: (cmd: string) => void)` | unsubscribe fn | menu commands: `'open' \| 'paste' \| 'clear' \| 'copy-primary'`, plus `'settings-changed'` (re-read `getSettings()`; sent when View ▸ auto-scan is toggled or `setSetting` changes a value) |
| `getSettings()` / `setSetting(key, value)` | | only `autoScanClipboard: boolean` (default true). Stored in memory + a tiny JSON in userData — settings only, never content |

```ts
type ScanResult = {
  id: string,                      // random
  source: { kind: 'drop'|'paste'|'file'|'open-with'|'clipboard-auto'|'text', name?: string },
  ok: boolean,
  error?: { code: string, message: string },
  image?: { previewDataUrl: string, width: number, height: number, format: string, pages: number },
  codes: HelperCode[],              // as in helper output
  text?: string                     // for source.kind === 'text' (pasted plain text): shown/parsed directly
}
```

ScanResult details (implemented in `src/main/decoder.js`):
- `image.width/height` = decoded raster of page/frame 0; extra fields `previewWidth`,
  `previewHeight`, `previewPage` describe the preview. `codes[].bounds/corners` are
  normalized and apply to the preview (page = `previewPage`).
- Main-side error codes besides the helper's: `decoder_unavailable` (helper/profile missing or
  sandboxed self-test failed — fail closed), `timeout`, `read_error`, `too_many_files` (>100
  files; extra result appended), `clipboard_empty`.
- `pasteFromClipboard()`: Finder file copies → one result per file (`source.kind 'paste'`,
  name = base name); else image (`name 'Clipboard image'`); else text (`kind 'text'`).
- Pushes (`onScanResults`): one array per batch — Finder Open With / dock drop (events within
  120 ms are batched), dev argv files at startup, `clipboard-auto` on window focus (only when
  the clipboard holds a NEW image or image-type file(s) and ≥1 code was found; text is never
  read automatically). Pushes before the page finished loading are queued.
- `decodeImage` rejects (preload `RangeError`) for > 64 MiB; empty bytes → `empty_input` result.


## Parsers contract (`src/renderer/parsers/index.js`)

`analyzePayload({ text, bytesBase64, bytesKind, symbology }) → Analysis` — pure, synchronous,
never throws (TOTP code generation is separate and async via WebCrypto). Pass the helper's
`HelperCode` fields as is.

```ts
type Analysis = {
  type: 'url'|'wifi'|'contact'|'otp'|'otp-migration'|'email'|'phone'|'sms'|'geo'|'event'
       |'crypto'|'epc-payment'|'swiss-qr-bill'|'payment'|'json'|'text'|'binary',
       // 'payment' = SPD, EMVCo/Pix, UPI, Bezahlcode etc. (see PAYLOADS.md §0.4)
  title: string,                   // e.g. "Website link", "Wi-Fi network"
  summary: string,                 // one-line human summary
  fields: Array<{ label: string, value: string, sensitive?: boolean, mono?: boolean, copy?: boolean }>,
  warnings: Array<{ level: 'info'|'caution'|'danger', message: string }>,
  actions: Array<{ kind: 'copy'|'open'|'save', label: string, value: string, sensitive?: boolean,
                   saveAs?: { suggestedName: string, kind: 'vcf'|'ics'|'txt'|'bin' } }>,
  data: { format: string, ... },   // format = precise sub-format id (e.g. 'wifi-zxing', 'vcard-3.0', 'pix'); plus type-specific structured data
  raw: { text: string, escaped: string, hasInvisible: boolean, length: number, bytesHex?: string,
         byteLength?: number, bytesKind?: 'payload'|'raw'|null,
         encoding?: 'utf-8'|'shift_jis'|'iso-8859-1', // set when text was decoded from payload bytes
         systemText?: string,        // Vision's text when it differs from ours (offer as alternative view)
         hiddenText?: string }       // ASCII smuggled in Unicode tag characters
}
```

`raw.text` is the decoded text untouched (`length` in code points). `warnings` are sorted
danger → caution → info and include the text-safety warnings of `raw.text`.

**Dispatch** (PAYLOADS.md §0.3). Text choice: with `bytesKind: 'payload'` the bytes are
decoded UTF-8 → Shift_JIS → ISO-8859-1, or classified `binary`; otherwise Vision's `text` is
used. Detection runs on the BOM-stripped, trimmed text. Order:
`structuredParsers` (rows 2–20) → URL (`url.js`, rows 19 + 21) → JSON (`json.js`) →
late parsers (rows 23–25) → text (`text.js`). A throwing `detect` is skipped; a throwing
`parse` falls back to text with an info warning; a `parse` returning `null` declines.

**Format registry** (`src/renderer/parsers/formats/registry.js`, owned by the structured-
formats module): `export const structuredParsers = [...]` (ordered), optionally
`export const lateParsers = [...]` (or entries with `phase: 'late'`) for heuristics that must
run after URL/JSON. Each entry: `{ id, detect(text, ctx) → boolean, parse(text, ctx) →
Analysis-without-raw | null }` with
`ctx = { bytes: Uint8Array|null, bytesKind, symbology, encoding, textSafety, analyzeUrl }`
(`textSafety(str, { context?: 'text'|'single-line'|'url', label? })` and `analyzeUrl(str)` are
the functions below, for per-field checks and embedded links).

Shared helpers (importable by format modules): `text-safety.js` (`textSafety`,
`escapeForDisplay`, `mixedScriptWarnings`, `scriptProfile`, `wholeScriptConfusable`,
`skeleton`, `codePointName`), `url.js` (`analyzeUrl`, `analyzeDomain` — host/IDN/PSL/brand
checks for e-mail domains etc., `detectUrl`, `OPENABLE_SCHEMES`), `psl.js` (`lookup`),
`punycode.js` (`decode`, `encode`, `domainToUnicode`), `bytes.js`.

Each type parser lives in its own file and has unit tests. Text safety analysis
(invisible / bidi / control chars, mixed scripts, confusables) applies to every type.

## Security model (summary — details in docs/SECURITY.md)

- BrowserWindow: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`,
  `webviewTag: false`, `spellcheck: false`, in-memory session partition, strict CSP,
  content served from a custom privileged `app://` protocol (no `file://`),
  navigation and `window.open` blocked, all permission requests denied, all
  network requests outside `app://` cancelled.
- Untrusted image parsing happens only in the short-lived, sandbox-exec'd helper.
- Electron fuses flipped on the built .app (RunAsNode off, NodeOptions off,
  inspect args off, cookie encryption on, only-load-from-asar if feasible…).

## Verification

`npm run verify` → launches the real app (Playwright `_electron`), performs real
interactions (real system clipboard + Cmd+V, renderer drop events with real file
bytes, Open dialog stubbed only at the dialog boundary), writes screenshots into
`verify-output/`. `npm test` = unit tests; `npm run test:e2e` = e2e suite (dev binary);
`npm run test:packaged` = the packaged test variant bundle (SECURITY.md §6.6).
AGENTS.md documents how to do ad-hoc checks (launch, evaluate, screenshot).
