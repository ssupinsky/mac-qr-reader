## 2. Threat model

Assets: decoded payloads (OTP secrets, Wi-Fi passwords, crypto addresses, URLs), the user's
files and clipboard, and the machine itself.

| Threat | Main mitigations |
|---|---|
| Malicious image/PDF exploits a decoder bug (ImageIO, CoreGraphics PDF, Vision) | Parsing only in the short-lived helper under `(deny default)` sandbox: even with code execution it cannot open sockets, write files, read `$HOME`, exec, or talk to the pasteboard (§7). Renderer only ever sees the helper's re-encoded PNG preview, never the original bytes. |
| Malicious payload text (XSS, bidi/invisible tricks, `javascript:` URLs) | Rendering via `textContent` only; CSP + Trusted Types make HTML sinks throw [tested]; links opened only by main after allowlist + native confirm (§5.9). |
| Compromised renderer | Chromium sandbox, context isolation, minimal preload, IPC sender/arg validation, no navigation, no network (§5). |
| Supply chain (npm, mirror, GitHub release) | Two dev deps only, exact pins, lockfile integrity, independent cross-checks (deps.dev, jsDelivr, npm signatures via Sigstore TUF, GitHub attestations), no lifecycle scripts, no install-time code from npm executed (§3, §4). |
| Local "living-off-the-land" abuse of our app (run-as-node, NODE_OPTIONS, `--inspect`, `--remote-debugging-port`, DYLD injection, swapped app code) | Fuses, ASAR integrity, refuse debug switches in main, hardened runtime (§6). |
| Network exfiltration | No network by design: `webRequest` cancels all non-`app://qr/` requests [tested], CSP `connect-src 'none'`, helper has no sockets and cannot reach trustd (which would fetch AIA/OCSP URLs for it) [tested: `test/native/sandbox.test.mjs`], no crash reporter, no updater. Residual: the helper can still talk to the few system daemons it needs (logd, cfprefsd, opendirectoryd, ANE/GPU); none is known to fetch URLs (§7.4). |
| Data at rest | No history; in-memory partition; verify script greps disk for a canary (§9). |

Out of scope: an attacker who already runs code as the user with full disk access (they can
read process memory of unhardened processes, edit `start.sh`, etc.).

## 3. npm dependencies

### 3.1 Version selection [tested]

- Electron supports the latest **three** stable majors [1]: today **45, 44, 43**
  (45 stable 2026-10-20, EOL 2027-04-27 tentative [2]). 46 is alpha.
- GitHub has `v45.3.0…v45.3.4` (2026-11-10 → 11-17) [3], but the corporate mirror
  `npm.dev.wixpress.com` **does not serve any 45.3.x yet** (`npm view electron@45.3.0` → E404;
  its `latest` dist-tag is 45.2.3). Public npmjs is blocked, so **45.2.3 is the newest
  installable 45.x** and is also past the 7-day cooling period (14 days).
- Security status of 45.2.3: none of the Electron GHSA advisories [4] cover it (the most
  recent, GHSA-jr5w-w6x2-84p9 eMudhra certs, was fixed in 45.0.0-beta.6). OSV and deps.dev
  list no advisories for `electron@45.2.3` [tested].
- What 45.3.x adds: 45.3.2 "Backported fixes from upstream ANGLE, Chromium, Dawn, Skia and V8"
  + Chromium 156.0.8078.100; 45.3.1 stops trusting revoked eMudhra RSA intermediates. These
  are relevant to apps that render web content/TLS; our renderer loads only our own files,
  never touches the network, and never decodes untrusted images (helper-generated PNG
  previews only), so exposure is low. **Action:** when the mirror serves ≥ 45.3.2 and it is
  ≥ 7 days old, bump (re-run §11).
- **Electron 45 API changes that matter here** (from the 45.0.0 notes [5] and the shipped
  `electron.d.ts`):
  - `clipboard` is now the W3C-style **async** API: `read()`, `readText()`, `has()`,
    `write([ClipboardItem])`, `writeText()`, `clear()`. `readImage`, `availableFormats`, etc.
    are gone (`clipboard.availableFormats is not a function` [tested]).
  - Sandboxed preloads no longer get `Buffer`, `events`, `timers`, `url`, `setImmediate`,
    `clearImmediate`.
  - `protocol.registerSource` exists but is `@experimental` → we use stable `protocol.handle`.
- playwright-core: 1.64.1 is the latest stable on the mirror (2026-10-14, 35 days old).

### 3.4 `.npmrc` (project)

```ini
registry=https://registry.npmjs.org/
ignore-scripts=true
save-exact=true
min-release-age=7
allow-git=none
engine-strict=true
fund=false
audit=true
```

- `ignore-scripts=true` still lets `npm start` / `npm test` / `npm run x` run *that* script,
  but no `pre*`/`post*` hooks [14] — compatible with `npm start`.
- `min-release-age=7` (npm ≥ 11.x) refuses versions younger than 7 days **[tested]**: with
  `=30` npm fails `ETARGET … electron@45.2.3 with a date before 10/19/2026`; with `=7` it
  resolves the identical lockfile. Works through the mirror (it serves `time`).
- `allow-git=none` blocks git dependencies (a common worm vector) [14].

### 3.5 Lockfile allowlist

Commit `package-lock.json`. `scripts/setup.mjs` must, before `npm ci`, parse the lockfile and
compare `{path, version, integrity}` of every entry against a committed allowlist (the table
in §3.2); any addition/change → stop with a clear message. `npm ci` then enforces the
sha512 integrity of every tarball. Updating = edit `package.json`, `npm install` in a scratch
copy, repeat §3.3, update allowlist + this file.

## 4. Electron binary integrity

### 4.1 Facts [tested]

- `install.js` calls `@electron/get` `downloadArtifact({version, checksums: require('./checksums.json'), …})`.
  `@electron/get` writes the `checksums.json` entries into a temp `SHASUMS256.txt` and
  validates the download with `sumchecker` (SHA-256). It only fetches a remote
  `SHASUMS256.txt` if `electron_use_remote_checksums` is set. A cached zip is re-validated on
  every use. Downloads go to `https://github.com/electron/electron/releases/download/v45.2.3/`
  unless overridden.
- **Env vars that change this behaviour** (all read by install.js/@electron/get):
  `ELECTRON_MIRROR`, `ELECTRON_CUSTOM_DIR`, `ELECTRON_CUSTOM_FILENAME`, `ELECTRON_CUSTOM_VERSION`,
  `NPM_CONFIG_ELECTRON_*`, `npm_config_electron_*`, `npm_package_config_electron_*`,
  `electron_use_remote_checksums`, `electron_config_cache`, `force_no_cache`,
  `ELECTRON_OVERRIDE_DIST_PATH`, `ELECTRON_INSTALL_PLATFORM/ARCH`, `npm_config_platform/arch`,
  `ELECTRON_GET_USE_PROXY`. (`ELECTRON_OVERRIDE_DIST_PATH` also affects `require('electron')`.)
  → setup must refuse to run if any of these are set, or scrub them.
- **Cache location:** `env-paths('electron').cache` → `~/Library/Caches/electron/<sha256(url dir)>/<file>`:
  `~/Library/Caches/electron/8f3ac71e340a9b80141ce76e61a0af56be8beee5aed0cf501a00bd07792a0295/electron-v45.2.3-darwin-arm64.zip`
  where `8f3ac71e…0295 = sha256("https://github.com/electron/electron/releases/download/v45.2.3")`.
- **Pinned hash** of `electron-v45.2.3-darwin-arm64.zip` (121 208 238 bytes):
  `4d7c429064087a47b855d9bd06c76ead4819b7f02b385de232d4a5c37ecef55f` — identical in
  (a) the npm package's `checksums.json`, (b) GitHub release `SHASUMS256.txt` (all 67
  entries of the two files match), (c) the GitHub API asset `digest`, and (d) the cached zip.
- **GitHub artifact attestation** exists and verifies: `gh attestation verify <zip> --repo electron/electron`
  → exit 0; SLSA v1 provenance, signer
  `electron/electron/.github/workflows/pipeline-segment-electron-publish.yml@refs/tags/v45.2.3`,
  source commit `d0a18d02058b21ff292e25d5f53f00bd120f2f61`, run `41872094845`.
- **Electron's macOS zips are NOT Developer-ID signed** — every Mach-O is only
  *linker-signed ad-hoc* (`flags=0x20002(adhoc,linker-signed)`, `TeamIdentifier=not set`,
  no `_CodeSignature/`). So there is **no Electron Team ID to check**;
  `codesign --verify --deep --strict` on the stock `Electron.app` **fails** (exit 1, "code has
  no resources but signature indicates they must be present") and `spctl` rejects it. This is
  expected; integrity rests on the SHA-256 + attestation. Signature checks are meaningful
  only on **our** re-signed bundle (§6.4).
- `ditto -x -k` extraction is **byte-identical** to `@electron-internal/extract-zip`'s
  (`diff -r --no-dereference`, incl. the 14 framework symlinks).

### 4.2 Recommended setup procedure (no npm install code executed)

```text
1. Refuse if any env var from §4.1 is set.
2. npm ci   (scripts disabled by .npmrc; lockfile allowlist checked first, §3.5)
3. Fast path: dist/version == "45.2.3", path.txt == "Electron.app/Contents/MacOS/Electron",
   the marker from step 7 == pinned hash, AND every file under dist re-hashes to the
   manifest recorded at extraction (`dist/.verified-manifest.json`: per-file SHA-256 + exec
   bit + symlink targets, no extra/missing files; 275 entries, ~0.2 s) → done. Any change
   (tested: one byte in default_app.asar) → falls through and re-extracts.
4. Make a private temp dir (mkdtemp, 0700). If the cache zip
   ~/Library/Caches/electron/8f3ac71e…0295/electron-v45.2.3-darwin-arm64.zip exists, COPY it
   there; else download https://github.com/electron/electron/releases/download/v45.2.3/electron-v45.2.3-darwin-arm64.zip
   with curl straight into the private dir (then also copy it into the cache).
   Every later step uses only the private copy: the file hashed is the file extracted (no TOCTOU).
5. sha256(copy) MUST equal the constant 4d7c4290…ef55f pinned in setup.mjs
   AND checksums.json["electron-v45.2.3-darwin-arm64.zip"]. Mismatch → delete cache file, abort.
   When online: fetch SHASUMS256.txt from the same release and compare too (mismatch fatal).
   `gh attestation verify <copy> --repo electron/electron`: **fatal on failure when `gh` is
   installed and authenticated** (`gh auth status` = 0); a warning when gh is absent/logged out.
6. rm -rf node_modules/electron/dist && mkdir it; `/usr/bin/ditto -x -k <copy> node_modules/electron/dist`
   (execFile, no shell). Write path.txt = "Electron.app/Contents/MacOS/Electron" (no newline).
7. Write dist/.verified-manifest.json and dist/.verified-sha256 = pinned hash (setup markers).
   Note: the manifest guards against accidental/after-the-fact modification of dist; a
   same-user attacker could rewrite it too (out of scope, §2).
```

### 5.2 Custom protocol (instead of `file://`) [tested]

```js
// before app 'ready':
protocol.registerSchemesAsPrivileged([{ scheme: 'app', privileges: { standard: true, secure: true } }]);
// after ready — IMPORTANT: register on the *window's* session; `protocol.handle` on the
// global `protocol` module only covers defaultSession.
ses.protocol.handle('app', (req) => {
  const u = new URL(req.url);
  const f = req.method === 'GET' && u.host === 'qr' && FILES[u.pathname]; // static map, no fs path from URL
  if (!f) return new Response('Not found', { status: 404 });
  return new Response(fs.readFileSync(f.abs), { headers: {
    'content-type': f.mime, 'content-security-policy': CSP, 'x-content-type-options': 'nosniff',
    'cross-origin-opener-policy': 'same-origin', 'cross-origin-resource-policy': 'same-origin',
    'referrer-policy': 'no-referrer' } });
});
```

- `standard` (relative URLs, origin `app://qr`) + `secure` (secure context) are sufficient;
  ES module imports work [tested]. Do **not** set `bypassCSP`, `corsEnabled`,
  `supportFetchAPI`, `allowServiceWorkers`, `codeCache` (writes V8 cache to disk),
  `allowExtensions`, `stream`.
- `FILES` = an explicit map `{'/index.html': {abs, mime}, …}` built at startup from the
  bundled renderer directory. Traversal attempts (`/../../etc/hosts`, `/%2e%2e/main.js`)
  are normalised by the URL parser and then 404 [tested].
- `protocol.registerSource` (experimental in 45) is not used.

### 5.9 `shell.openExternal`

`openExternal` hands the URL to LaunchServices, which will launch **whatever app handles
the scheme** (including `file:` → could open/execute local files, and arbitrary custom
schemes) [15]. Rules:

1. Only from main, only after the native confirm dialog (`dialog.showMessageBox` with
   `type:'warning'`, default button = Cancel, `cancelId` = Cancel).
2. Re-parse in main: `const u = new URL(s)`; allow `u.protocol ∈ {'https:', 'http:',
   'mailto:', 'tel:', 'sms:'}` (`facetime:` only if really wanted — it starts a call UI).
   Reject everything else (`file:`, `javascript:`, `data:`, `blob:`, `app:`, custom schemes,
   `x-apple-*`). Reject if `u.username || u.password` for http(s) (or show prominently),
   length > 2048, or control/bidi/invisible characters in the original string.
3. Show the **normalised** `u.href` and the host both as punycode (`u.hostname`) and
   decoded Unicode, flag IDN/mixed-script hosts, and call `openExternal(u.href)` with
   exactly what was shown. Implemented (`src/main/ipc.js` + `linkinfo.js`) [tested:
   `test/e2e/external.test.mjs`]: the bold **message** holds `Site:` (registrable domain
   via the bundled PSL — `src/renderer/parsers/psl.js`, loaded in main with dynamic
   `import()`; omitted for IPs/local names) and `Host:` (+ `Host (Unicode):`), each wrapped
   in U+2066…U+2069 bidi isolates; the detail shows the href truncated to 300 characters +
   "… (N more characters)" (the exact href is opened); a warning line for loopback, private
   (RFC 1918, fc00::/7), link-local (169.254/16, fe80::/10), CGNAT (100.64/10), unspecified,
   IPv4-mapped IPv6, `localhost`/`*.localhost` and `*.local` hosts. The dialog says "Opens
   with the default app for this link" — LaunchServices picks the handler, we don't know it.
4. Do not grant the `openExternal` permission to web content (handler denies it; see
   GHSA-997q-gvvc-jwmx, fixed in ≤ 45.0.0-alpha.5).

### 6.2 Tooling: no new dependency

`@electron/fuses@2.1.3` was vetted (0 deps, ~10 KB JS, provenance, npm sig OK, deps.dev

`dL7pKGdnNz796PbbjQWNKmHXBZaB9tsX` exactly once in
`Contents/Frameworks/Electron Framework.framework/Electron Framework`, require version byte
`1` and length ≥ 9, refuse `'r'` (removed) bytes, write `'0'`/`'1'`, read back and assert)
produced a **byte-identical** binary to `@electron/fuses` with the same config [tested].
Same for ASAR: `@electron/asar` would add `glob` + `minimatch`; a ~40-line packer (pickle
header: `UInt32LE 4`, `UInt32LE headerPickleSize`, then `UInt32LE payloadSize`,

### 6.3 Build order for `build/QR Reader.app`

1. `ditto` the verified `node_modules/electron/dist/Electron.app` → `build/QR Reader.app`
   (rename executable/bundle id/name in Info.plist as desired; keep helper app names
   consistent with `CFBundleExecutable` rules of Electron).
2. Delete `Contents/Resources/default_app.asar`.
3. Pack `src/` (main, preload, renderer) → `Contents/Resources/app.asar` (with per-file
   integrity); copy `qr-decode` + `qr-decode.sb` to `Contents/Resources/bin/` (outside the
   asar so they can be exec'd).
4. **Replace** the whole `ElectronAsarIntegrity` dict in Info.plist (stock Electron ships
   one for `Resources/default_app.asar`; `PlistBuddy Add` fails with "Entry Already
   Exists") with `{ "Resources/app.asar": { algorithm: "SHA256", hash: <header sha256> } }`.
5. Flip fuses (§6.1).
6. Sign last (any later change invalidates the signature):
   `codesign --force --deep --sign - --options runtime --entitlements build/entitlements.plist "build/QR Reader.app"`
   with entitlements:
   ```xml
   <key>com.apple.security.cs.allow-jit</key><true/>
   <key>com.apple.security.cs.disable-library-validation</key><true/>
   ```
   `disable-library-validation` is required for ad-hoc signing: without it the hardened
   runtime refuses to load `Electron Framework` ("Library not loaded") because ad-hoc code
   has no Team ID [tested]. Do not add `allow-dyld-environment-variables`,
   `allow-unsigned-executable-memory` or `get-task-allow`. **Before** signing the bundle,
   sign the helper: `codesign --force --sign - --options runtime Contents/Resources/bin/qr-decode`
   (no entitlements; `--deep` does not reach `Resources/bin`, but the bundle's resource seal
   then covers it). The runtime-signed helper gave identical results on all 54 fixtures
   under the sandbox [tested].
7. Verify: `codesign --verify --deep --strict "build/QR Reader.app"` → "valid on disk /
   satisfies its Designated Requirement" [tested]; read the fuse wire back.

### 6.4 What signing does and doesn't give us

- Ad-hoc = integrity seal (cdhash) only; no identity. `spctl --assess` → **rejected** (expected;
  the app is built locally and not quarantined, so Gatekeeper does not block it).
- Hardened runtime: `DYLD_INSERT_LIBRARIES=evil.dylib` ran the dylib's constructor in the
  main + 3 helper processes of the plain ad-hoc build; **with `--options runtime` it was
  ignored** [tested]. Also prevents debugger attach (no `get-task-allow`).
- Each rebuild changes the cdhash; Keychain/TCC grants keyed on it would re-prompt. We use
  neither (cookie encryption never creates a Keychain item without cookies).
- `com.apple.provenance` xattr is set by macOS on files created by our tools; harmless.

## 7. Helper sandbox (`native/qr-decode.sb`)

### 7.1 Result

A working **`(deny default)`** profile exists; no fallback needed. It imports Apple's
`/System/Library/Sandbox/Profiles/system.sb` (the baseline Apple's own daemons use:
read-only `/System`, `/usr/lib`, `/usr/share`, dyld support, `sysctl-read`, core daemon
mach-lookups; **no direct network, no writes** except `/dev/null|zero|fd/*`, `/dev/dtracehelper`,
`/cores/*` when core dumps are enabled) and adds only:

```scheme
(allow process-exec (literal (param "HELPER")))
(allow file-read* (literal (param "HELPER")) (literal (param "HELPER_DIR")))
(allow mach-lookup (global-name "com.apple.appleneuralengine"))
(allow iokit-open-user-client
       (iokit-user-client-class "IOSurfaceRootUserClient")
       (iokit-user-client-class "IOSurfaceAcceleratorClient")
       (iokit-user-client-class "AGXDeviceUserClient")
       (iokit-user-client-class "H11ANEInDirectPathClient")
       (iokit-user-client-class "H1xANELoadBalancerDirectPathClient")
       (iokit-user-client-class "AppleVirtIONeuralEngineDeviceUserClient"))
```

**Explicit denials after the import** (SBPL: the last matching rule wins). `system.sb`
allows mach-lookup of `com.apple.trustd`; evaluating an attacker-chosen certificate with
network fetch enabled makes trustd (outside our sandbox) GET the certificate's AIA
caIssuers / OCSP / CRL URLs — a network channel out of the helper [tested: a request reached
a local listener from the old profile]. Now denied, together with other endpoints the helper
does not need:

```scheme

      (global-name "com.apple.analyticsd") (global-name "com.apple.analyticsd.messagetracer"))
(deny network-outbound (literal "/private/var/run/syslog"))
(deny mach-lookup (global-name "com.apple.diagnosticd") (global-name "com.apple.runningboard")
      (global-name "com.apple.system.notification_center") (global-name "com.apple.espd")
      (global-name "com.apple.dt.automationmode.reader") (global-name "com.apple.appsleep")
      (global-name "com.apple.xpc.activity.unmanaged"))
(deny file-read* (literal "/private/etc/passwd") (literal "/private/etc/master.passwd"))
(deny sysctl-read (sysctl-name-prefix "kern.proc"))
```

Each was checked: full JSON output of all 54 fixtures byte-identical before/after, no
measurable slowdown. **Not** denied: opendirectoryd/libinfo lookups (denying adds ~30 ms per
scan through retries; local account lookups only), `com.apple.logd` (local logging).

The full file (with comments) is `native/qr-decode.sb`. The IOKit class list is exactly what
Apple grants its own Vision/ML daemon `com.apple.textunderstandingd` and App Sandbox apps
(`appsandbox-common.sb`), so it should hold across Apple-silicon generations.

### 7.2 Invocation contract (main)

```js
const helper = fs.realpathSync(path.join(resDir, 'bin/qr-decode'));
const sb = fs.realpathSync(path.join(resDir, 'bin/qr-decode.sb'));
const child = spawn('/usr/bin/sandbox-exec',
  ['-f', sb, '-D', `HELPER=${helper}`, '-D', `HELPER_DIR=${path.dirname(helper)}`, helper, '--preview-max', '1600'],
  { cwd: '/', env: { PATH: '/usr/bin:/bin' }, stdio: ['pipe', 'pipe', 'pipe'] });
```

- **Real paths are mandatory** (the sandbox matches canonical paths: `/private/tmp`, not
  `/tmp`; resolve symlinks in `~/Documents/...`).
- `cwd: '/'` (otherwise frameworks try to read the cwd → denial) and a minimal env (no
  `HOME`, no `DYLD_*`).
- Cap stdout (e.g. 32 MiB) and stderr (64 KiB), enforce the 20 s timeout with SIGKILL,
  treat any non-JSON stdout as `decode_error`. Parse only the **last line**.
- **Framework noise on stdout:** in a test build using PDFKit/CIContext, CoreML's E5RT
  printed `E5RT encountered an STL exception … ~/Library/Caches/<name>/com.apple.e5rt.e5bundlecache`
  **to stdout** when its model cache could not be written. The real `qr-decode.swift` did not
  trigger it, but the helper should still protect its channel: at startup
  `let out = dup(1); dup2(2, 1)` and write the JSON to `out`.
- **Integrity:** `scripts/build-app.mjs` signs the helper, then writes the SHA-256 of
  `Resources/bin/qr-decode` and `Resources/qr-decode.sb` into `app.asar` as
  `src/main/helper-hashes.json` (generated into the asar only, never into the repo; covered
  by the embedded ASAR integrity fuse). `paths.verifyHelper()` checks both before the
  self-test and again before every helper run (~1 ms); a mismatch → `decoder_unavailable`
  (fail closed) [tested: one appended byte in the packaged profile]. `verifyApp` checks the
  same at build time. Dev runs (unpackaged) skip the check: they execute the just-built
  `build/bin/qr-decode` + `native/qr-decode.sb` and there is no recorded hash.
- Memory: the helper caps itself (stage-boundary `phys_footprint` check, 1 GiB → `too_large`)
  and works on ≤ 24 MP rasters, one page at a time; measured peaks ≤ ~610 MB (ARCHITECTURE.md).
  With `MAX_CONCURRENT = 2` helpers the worst case is ~2 GiB, typical ≤ 1.2 GB.
- If sandboxing ever breaks after a macOS update, the helper crashes or Vision returns no
  codes **silently**. Setup must run a self-test (decode a known fixture through
  `sandbox-exec` and require the expected payload) and the app should show "decoder
  unavailable", never fall back to running unsandboxed.

### 7.3 Evidence [tested]

- Built via minimisation: started with `(deny default)` and iterated on violations read from
  `/usr/bin/log show --predicate 'sender == "Sandbox"'` (note: in zsh, `log` is a builtin —
  use `/usr/bin/log`). Then removed each rule one by one; every remaining rule is required
  (without any of them: 0/5 formats decode). Removing GPU/ANE access does **not** produce an
  error — Vision silently returns zero codes (and a CPU-only `setComputeDevice` variant still
  needs IOSurface and also returned nothing).
- Real helper (`native/qr-decode.swift`, built in scratch) on **all 54 fixtures** from
  `gen-fixtures` (PNG, JPEG incl. EXIF orientation, HEIC, AVIF, WebP, GIF incl. animated,
  TIFF, BMP, ICO, 2-page PDF, 81 MP PNG, huge-dimension, truncated/garbage, SVG, text, zip,
  empty, QR/MicroQR/Aztec/PDF417/Code128, multi-code): output **identical** sandboxed vs.
  unsandboxed (0 diffs); ~0.2 s per image, 1.05 s for 81 MP. A test build with PDFKit +
  CoreText text PDF + CIContext also worked.
- Adversarial binary under the profile (control run unsandboxed succeeded at all of these):
  read `~/.zshrc` → denied; list `~/Documents` → denied; read `/etc/hosts` → denied; list
  `$TMPDIR` → denied; write `/tmp`, `$TMPDIR`, `~/Library/Caches` → denied; TCP connect
  1.1.1.1:443 → EPERM; UDP 8.8.8.8:53 → EPERM; `getaddrinfo` → fails; `URLSession` → fails;
  exec `/bin/sh` → denied; `NSPasteboard.general` read → nil.
- Regression tests `test/native/sandbox.test.mjs` (probes in `test/native/probes/`, compiled
  into `build/test-probes/`): (1) `aia-probe` evaluates a leaf cert whose AIA/OCSP/CRL URLs
  point at a local HTTP listener with a unique token — unsandboxed control → request arrives;
  under the profile → none within 3 s (the pre-fix profile fails this test); (2)
  `sandbox-probe` — TCP connect to loopback, create a file in `/private/tmp`, list `$HOME`, read
  a file under `$HOME`, syslog socket, `/etc/passwd`, process list, `notify_post`, lookups of
  trustd/analyticsd/diagnosticd/runningboard: all succeed unsandboxed, all denied sandboxed.
- Harmless denials left in place: E5RT model-cache writes, `$HOME`/`/private/var/folders`
  metadata, `kCFPreferencesAnyApplication`, `~/.CFUserTextEncoding`, WindowServer, tccd,
  DiskArbitration, coreservicesd, launchservicesd, dock.
- Note: when the helper runs **unsandboxed** (dev experiments), Vision creates
  `~/Library/Caches/qr-decode/com.apple.e5rt.e5bundlecache/…` (compiled model, no user data).

### 7.4 Caveats

- `sandbox-exec` is marked **DEPRECATED** in its man page (since 2017) but is still shipped
  and enforced on macOS 26.6.2; Apple's alternative (App Sandbox entitlements) would make
  the helper create a container under `~/Library/Containers` (disk writes) and needs a real
  bundle id; `sandbox-exec` is the better fit for a stdin→stdout filter. The profile is
  applied before the helper's first instruction (unlike in-process `sandbox_init`).
- `system.sb` is Apple-private and may change; failure mode is closed (see §7.2 self-test).
- GPU/ANE driver interfaces remain reachable from the helper (required by Vision) — a
  kernel-driver exploit chain is the residual risk.
- Main must still enforce input size (64 MiB) and timeout; the sandbox does not limit memory
  (the helper's own 1 GiB footprint check does, between stages).
- Daemons still reachable via `system.sb` (logd, cfprefsd, opendirectoryd, secinitd,
  dirhelper, ANE) are not known to fetch anything on a client's behalf; re-run
  `test/native/sandbox.test.mjs` and the reviewer's probe on every macOS update.

## 8. Clipboard & macOS pasteboard privacy

### 8.1 macOS 26 behaviour

- Since macOS 15.4, `NSPasteboard` has `accessBehavior` (`default/ask/alwaysAllow/alwaysDeny`)
  and `detect…` APIs. The SDK header (macOS 26 SDK, `NSPasteboard.h`) says: *"The default
  behavior for the General pasteboard is to ask upon programmatic access"*; user-initiated,
  paste-related access is exempt [18][19].
- On macOS 15.4–26 this is a **developer preview**, enabled per app with
  `defaults write <bundle-id> EnablePasteboardPrivacyDeveloperPreview -bool yes` [19].
  Reports indicate it is still not enforced by default as of late 2026 [20].
- **[tested]** on macOS 26.6.2 without the preview flag: a Swift CLI reported
  `accessBehavior = 2 (alwaysAllow)`; Electron 45 `clipboard.read()`/`readText()` in main,
  with no user action, returned in ~25 ms with no prompt.
- macOS 26.4's "paste protection" is a **Terminal-only** warning about pasted commands [21];
  irrelevant here.

**Design consequence for "auto-scan clipboard on window focus":** works silently today; when
Apple enforces pasteboard privacy, every focus-triggered read would show a system alert. So:
keep it a setting (default on is fine on macOS 26), first probe with
`clipboard.has('image/png')` / file-URL types (type metadata only) and read only if an image
or file is present, never read text automatically, and make the explicit paths (Cmd+V via the
`paste` role → renderer `paste` event `clipboardData`; menu "Paste") the primary UX — those
are user-initiated and exempt.

### 8.2 Sensitive copies [tested]

```js
const MARK = 'electron application/osclipboard;format="local.qr-reader.sensitive"';
await clipboard.write([new ClipboardItem({
  'text/plain': value,
  'electron application/osclipboard;format="org.nspasteboard.ConcealedType"': '',
  'electron application/osclipboard;format="org.nspasteboard.TransientType"': '',
  'electron application/osclipboard;format="org.nspasteboard.AutoGeneratedType"': '',
  [MARK]: '',
})]);
// after 60 s:
if (await clipboard.has(MARK)) clipboard.clear();
```

- Verified the pasteboard then carries `org.nspasteboard.ConcealedType`, `…TransientType`,
  `public.utf8-plain-text`; these nspasteboard.org markers [22] tell clipboard managers not
  to record the item.
- `has(MARK)` is true right after our write, **false after any other app copies**
  (`pbcopy`), so the auto-clear never wipes the user's newer clipboard and never needs to
  read the content (no future privacy prompt). Clear on app quit too (if `has(MARK)`).
- Residual: **Universal Clipboard (Handoff)** may sync the item to the user's other Apple
  devices; the concealed markers don't prevent that. AppKit's fix is
  `prepareForNewContents(with: .currentHostOnly)`, which Electron does not expose. Options:
  accept + show a note on sensitive copy buttons, or later add a tiny native writer (would
  need its own sandbox profile allowing only the pasteboard service — not built/tested).
- Prefer "reveal" + explicit "Copy" for secrets (OTP seeds, Wi-Fi passwords); never copy a
  secret automatically.

## 9. Disk footprint ("nothing decoded is ever written")

[tested] After a session with the in-memory partition, `~/Library/Application Support/<app>/`
still gets Chromium/Electron housekeeping for the **default** session (`Preferences`,
`Local State`, `GPUCache`, `DawnGraphiteCache`, `DawnWebGPUCache`, `Code Cache/` (empty
index), `Local Storage/leveldb` (only `VERSION`), `Shared Dictionary`, `Trust Tokens`,
`Network Persistent State`). **No string from our page/partition was found on disk**
(`localStorage`/`indexedDB` writes in the partition stayed in memory). Recommendations:

- `verify.mjs`: decode a fixture with a unique canary payload, quit, then
  `grep -r` the canary (and its base64) in userData, `~/Library/Caches/<app>`,
  `~/Library/Caches/qr-decode`, `$TMPDIR` → must find nothing.
- Keep `v8CacheOptions:'none'`, no `codeCache` privilege, no `crashReporter`, no
  `contentTracing`/`netLog`. Keep large `Blob`s short-lived (revoke object URLs).
- macOS crash reports for the helper (`~/Library/Logs/DiagnosticReports`) contain stacks,
  not heap contents.
- **Save… files are not quarantined** (no `com.apple.quarantine`). Evaluated 2026-11-18:
  the outputs are data files (.vcf/.ics/.txt, .bin written 0600 without exec bit) opened by
  Contacts/Calendar/editors, where Gatekeeper's quarantine check adds little. Doing it
  correctly means either `LSFileQuarantineEnabled` in Info.plist (quarantines *every* file the
  app writes, incl. Chromium's userData files) or writing the private `flags;hex-time;agent;uuid`
  xattr format by hand (undocumented flag bits). Not implemented; revisit if `.bin` exports
  of executables become a real use case.

## 10. Residual risks & follow-ups

1. Electron 45.2.3 lacks the 45.3.2 Chromium/V8 backports → bump when the mirror has ≥ 45.3.2
   for ≥ 7 days.
2. Mirror omits npm signatures for some packages and has no attestations endpoint → rely on
   deps.dev/jsDelivr cross-checks on each update (§11).
3. GPU/ANE driver attack surface from the helper (required by Vision).
4. `sandbox-exec`/`system.sb` deprecation; mitigated by fail-closed self-test.
5. Universal Clipboard sync of sensitive copies (§8.2).
6. Future macOS pasteboard prompts for auto-scan (§8.1).
7. Same-user malware with Full Disk Access is out of scope (it can also rewrite the bundle:
   the helper hashes in app.asar and the Electron dist manifest detect accidents/tampering
   after the fact, not an attacker who can re-sign).
8. Save… output is not quarantined (§9).

## 11. Re-verification checklist (run on every dependency/Electron bump)

```sh
N="fnm exec --using=24.18.0"; D=<scratch dir>; cd $D
$N npm view electron time --json --registry https://registry.npmjs.org   # age ≥ 7 days?
curl -s https://api.github.com/repos/electron/electron/security-advisories # new GHSAs?
$N npm install --ignore-scripts && $N npm ls --all && $N npm audit
# per package in package-lock.json:
#   deps.dev:  GET https://api.deps.dev/v3/query?hash.type=SHA512&hash.value=<b64 integrity>
#   jsDelivr:  GET https://data.jsdelivr.com/v1/packages/npm/<name>@<ver>?structure=tree (per-file sha256)
#   OSV:       POST https://api.osv.dev/v1/querybatch  (MAL-* + GHSA)
#   npm sigs:  verify dist.signatures with keys.json from tuf-repo-cdn.sigstore.dev (registry.npmjs.org role)
#   IOC lists: github.com/DataDog/indicators-of-compromise, github.com/wiz-sec-public/wiz-research-iocs
shasum -a 256 ~/Library/Caches/electron/<sha256(url-dir)>/electron-v<ver>-darwin-arm64.zip
curl -sSL https://github.com/electron/electron/releases/download/v<ver>/SHASUMS256.txt | grep darwin-arm64.zip
gh attestation verify <zip> --repo electron/electron
# rebuild, then:
codesign --verify --deep --strict "build/QR Reader.app"
# helper self-test under sandbox on all fixtures; Playwright verify on the dev binary
```
